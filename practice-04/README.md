## Организация кода

`task-service.js` — чистые операции над массивом задач ПР2/ПР3 + `updateTask`. Не работает с DOM, формой, storage. Возвращает `{ ok: true, tasks }` или `{ ok: false, error }`. Входной массив не мутирует.

`form-validation.js` — чистая `validateTaskDraft(draft, tasks, editingId)`. Нормализует id через `Number`, title через `trim()`, priority по белому списку. В режиме редактирования `draft.id` игнорируется, берётся `editingId`. Возвращает `{ ok: true, value }` или `{ ok: false, errors }`. Не обращается к `document`, форме и `localStorage`.

`task-storage.js` — `isValidTaskList`, `loadTasks`, `saveTasks`, `removeSavedTasks`. Все принимают объект `storage` аргументом. `loadTasks` всегда делает независимую копию `fallbackTasks`, проверяет `version` и `tasks` через `isValidTaskList`; при исключении/битом JSON/неверной схеме возвращает `fallback` с непустым `error`. `saveTasks` сначала валидирует список, потом пишет JSON-оболочку. `removeSavedTasks` удаляет только переданный ключ.

`task-view.js` — создание карточек, отрисовка списка, сводки, пустого состояния. Работает только с DOM.

`main.js` — связка: старт из storage, `renderApp`, `setFormMode`, `handleFormSubmit`, `handleTaskListClick` (toggle/edit/delete), `handleFilterClick`, `handleResetClick`. `renderApp` к storage не обращается.

`storage` передаётся аргументом, чтобы модуль оставался чистым и тестируемым через `MemoryStorage` в `modules.checks.js`, без зависимости от `window.localStorage`. Данные из JSON проверяются до использования, потому что после `JSON.parse` в хранилище может оказаться старая версия, повреждённые поля или дубли id; приложение должно не «упасть», а откатиться к исходному набору с предупреждением.
